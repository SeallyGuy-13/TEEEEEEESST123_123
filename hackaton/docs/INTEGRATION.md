# Игра про дрон — что уже подключено

В `minigames/drone/standalone.html` лежит **«Эко-Дрон: Чистый Берег»**: игрок
чертит маршрут беспилотника, экономит заряд, обходит ООПТ, ветер и облачность.
Игровая логика не переписывалась — добавлен мост с новеллой (блок «МОСТ С
НОВЕЛЛОЙ» в начале её `<script>`).

| Режим | Как открыт | Поведение |
| --- | --- | --- |
| В новелле | iframe в задаче «Обследование территории с помощью БПЛА» | ждёт `DRONE_START`, проходит столько участков, сколько задано в конфиге, затем показывает экран «Данные получены!» с блоком курса и крестиком возврата |
| Автономно | `minigames/drone/standalone.html` | то же самое, но без крестика: возвращаться некуда |

Сколько участков нужно облететь, задаётся в `data/minigames.json` (сейчас все пять):

```json
"drone": {
  "drone_level_01": { "id": "drone_level_01", "levels": 5 },
  "drone_full_campaign": { "id": "drone_full_campaign", "levels": 5 }
}
```

### Финальный экран и курс

На последнем участке показывается блок проекта «Чистый берег» с кнопкой
«Начать обучение» — она ведёт на курс:
`https://zaprirodu.ispring.ru/signup/LvEGzxy0_owor3LFnvf7L2qVk5I`

Внутри новеллы рядом появляется **крестик** в правом верхнем углу. Он не
закрывает экран сразу: первое нажатие раскрывает напоминание о том, что на
курсе много полезного, с двумя кнопками — «Посмотреть курс» (та же ссылка) и
«Вернуться к работе». Результат уходит в новеллу только по второй кнопке или по
повторному нажатию крестика (`askBeforeLeaving` → `sendDroneResult`).

Та же ссылка стоит на кнопках «Записаться на курс» и «Узнать о программе» в
экранах победы и поражения «три в ряд». Там сделано такое же напоминание: внутри
новеллы у экрана итога появляется крестик, а кнопка «Продолжить» сначала
раскрывает блок про курс и превращается в «Вернуться к работе» — результат
уходит только вторым нажатием. В автономном режиме и на стенде этого нет:
кнопка остаётся «Новое сканирование».

Уровни (их геометрия, ветер, туман, факты) описаны внутри самой игры, в массиве
`levels`. Чтобы новелла давала все пять участков, поменяйте `configId` в
`data/tasks.json` на `drone_full_campaign`.

Контракт сообщений — тот же по смыслу, что у «три в ряд»:

```js
// игра → хост
parent.postMessage({ type: 'DRONE_READY' }, '*');
parent.postMessage({ type: 'DRONE_EVENT', payload: { name: 'level', value: 2 } }, '*');
parent.postMessage({ type: 'DRONE_COMPLETE', payload: {
  levelsCompleted: 3, stars: 4, totalStars: 13, maxStars: 15, score: 1300
}}, '*');

// хост → игра
{ type: 'DRONE_START', payload: { levelId: 'drone_level_01', config: { levels: 3 } } }
```

Адаптер — `js/minigames/drone.js`, путь к странице задан в нём константой
`DRONE_URL`. Если игрок прошёл меньше участков, чем требует конфиг, результат
понижается до `failed`, и сценарий предложит облёт заново.

# Игра «три в ряд» — что уже подключено

В `minigames/match3/standalone.html` лежит **«Эко-Радар: Чистый Берег»** —
готовая игра. Её игровая логика не переписывалась: добавлен мост с новеллой
(блок «МОСТ С НОВЕЛЛОЙ» в начале её `<script>`) и исправлены две ошибки, из-за
которых уровень заканчивался на ещё не очищенном поле:

1. **Двойной учёт целей.** Фишка, которая превращается в бустер, остаётся на
   поле, но засчитывалась в собранное — и могла засчитаться повторно при каждом
   новом совпадении. Теперь в цель идёт только то, что реально убрано
   (`processDestroyQueue`, флаг `staysOnField`).
2. **«Линейный сканер» чистил и ряд, и столбец** — 15 клеток за раз, при целях
   12 и 8. В подсказке при этом написано «ряд или столбец». Введён отдельный тип
   `SPEC_COL`: горизонтальная четвёрка даёт сканер ряда, вертикальная — столбца.

До правок цели могли выполниться за один ход (счётчики прыгали до 21/13 при
целях 12/8).

Заодно пересчитан баланс уровня. Замер: за 25 ходов с поля снимается около
54 пластика и 41 нефти, поэтому цели подняты примерно до 2/3 от этого —
30 пластика и 20 нефти за 30 ходов. На прогоне уровень закрывается за 21 ход,
то есть с запасом, но без мгновенной победы. Цифры в `data/minigames.json`,
код для их изменения трогать не нужно.

## Как это работает

Игра живёт в двух режимах и сама определяет, в каком запущена
(`IN_IFRAME = window.parent !== window`):

| Режим | Как открыт | Поведение |
| --- | --- | --- |
| В новелле | iframe внутри задачи «Очистка территории» | ждёт `MATCH3_START` с уровнем, приветственный слайд туториала пропускает, показывает свой экран «Сектор очищен» с кнопкой **«Продолжить»** — результат уходит в новеллу только после нажатия |
| Автономно | `minigames/match3/standalone.html?level=<id>` | читает уровень из `data/minigames.json`, показывает свои экраны победы и поражения с кнопкой «Новое сканирование» |
| Стенд | `stand/match3.html?level=stand_cleanup_01` | уровень с `"standalone": true` — модалка игры не показывается, итог выводит крупный стендовый экран |

Важно: внутри новеллы результат отправляется **по клику игрока**, а не сразу.
Иначе новелла свернёт мини-игру и её экран победы мелькнёт на долю секунды.
Показывать ли собственный экран, игра решает по флагу `standalone` в конфиге
уровня (`showOwnGameOver`).

## Что где менять

| Задача | Файл |
| --- | --- |
| Ходы и цели уровня | `data/minigames.json` → `match3` |
| Какой уровень в какой задаче | `data/tasks.json` → `minigame.configId` |
| Реплики вокруг мини-игры | `js/script.js` → метки `CleanupGame`, `CleanupRetry`, `CleanupResult` |
| Путь к странице игры | `js/minigames/match3-adapter.js` → `MATCH3_URL` |
| Музыка внутри игры | `standalone.html` → `AUDIO_URL` (пустой — кнопка звука скрывается) |

### Типы фишек и ключи целей

В игре четыре типа: `1` пластик, `2` органика, `3` нефть, `4` металл.
Цели показываются только для **пластика и нефти** — так устроена её панель целей.

В `data/minigames.json` используйте ключи `plastic` и `oil`:

```json
"goals": [
  { "type": "collect", "item": "plastic", "count": 12 },
  { "type": "collect", "item": "oil", "count": 8 }
]
```

Ключ, которого игра не показывает (`glass`, `metal`, `bio`), будет проигнорирован
её панелью целей, но адаптер всё равно потребует его выполнения — и уровень
станет непроходимым. Соответствие ключей и типов задаётся в `standalone.html`
(`TYPE_KEYS` / `KEY_TYPES`).

# Если понадобится заменить игру на другую

Адаптер (`js/minigames/match3-adapter.js`) поддерживает два способа.

---

## Вариант A. Игра — отдельная HTML-страница (так сделано сейчас)

### 1. Положите игру на место текущей

Замените содержимое `minigames/match3/` своими файлами так, чтобы точкой входа
осталась `minigames/match3/standalone.html`.

Если путь другой — поправьте одну строку в `js/minigames/match3-adapter.js`:

```js
const MATCH3_URL = 'minigames/match3/standalone.html';
```

### 2. Добавьте в свою страницу обмен сообщениями

Новелла открывает страницу в `iframe` и общается с ней через `postMessage`.

**Игра → хост:**

```js
// сразу после загрузки: «я готова, присылайте уровень»
parent.postMessage({ type: 'MATCH3_READY' }, '*');

// по ходу игры (необязательно, идёт в метрики)
parent.postMessage({ type: 'MATCH3_EVENT', payload: { name: 'move', value: 1 } }, '*');

// уровень пройден
parent.postMessage({ type: 'MATCH3_COMPLETE', payload: {
  score: 1250,
  stars: 3,
  movesUsed: 18,
  collected: { plastic: 12, glass: 8 }   // ключи = item из целей уровня
}}, '*');

// ходы закончились, цели не выполнены
parent.postMessage({ type: 'MATCH3_FAIL', payload: { score: 400, collected: { plastic: 5 } } }, '*');

// игрок вышел
parent.postMessage({ type: 'MATCH3_ABORT' }, '*');
```

**Хост → игра:**

```js
window.addEventListener('message', (event) => {
  if (event.data.type === 'MATCH3_START') {
    const config = event.data.payload.config;
    // config.moveLimit, config.goals, config.theme — см. ниже
    startLevel(config);
  }
});
```

Важно: игра должна **дождаться `MATCH3_START`** и не начинать уровень сама,
иначе она сыграет не тот уровень, который просит новелла.

### 3. Проверьте

Откройте новеллу, выберите в трекере «Очистка территории», дойдите до
практического задания. Если игра не появилась — смотрите консоль:
хост пишет туда все проблемы.

---

## Вариант B. Ваша игра — JS-модуль (лучше в долгую)

Так игра живёт в общем DOM: нет iframe, общее аудио, общие стили, легче
отлаживать.

### 1. Подключите свой скрипт в `index.html`

```html
<script src="./minigames/match3/your-game.js"></script>
```

### 2. Объявите глобальный объект `Match3Game`

```js
window.Match3Game = {
  mount (container, config, callbacks) {
    // container — пустой div внутри оверлея новеллы
    // config    — конфиг уровня из data/minigames.json
    // callbacks — { onEvent, onComplete, onFail, onAbort }
  },
  unmount () {
    // снять слушатели, таймеры, canvas, аудио
  }
};
```

Адаптер сам увидит `window.Match3Game` и предпочтёт его iframe-варианту.
Результат передаётся в `callbacks.onComplete(result)` в том же формате, что и
в `MATCH3_COMPLETE`.

---

## Конфиг уровня

Лежит в `data/minigames.json`, секция `match3`:

```json
{
  "id": "cleanup_level_01",
  "mode": "moves",
  "moveLimit": 25,
  "goals": [
    { "type": "collect", "item": "plastic", "count": 12 },
    { "type": "collect", "item": "glass", "count": 8 }
  ],
  "theme": "shore_cleanup",
  "standalone": false
}
```

Ключи «Эко-Радара»: `plastic`, `oil` (показываются в целях), а также `bio` и
`metal` — они попадают в собранное, но целями быть не могут.
Если у вашей игры другие ключи — поменяйте их в `goals`, адаптер их не хардкодит.

Какой уровень запускается в какой задаче — задано в `data/tasks.json`:

```json
"minigame": { "type": "match3", "configId": "cleanup_level_01" }
```

## Как хост считает победу

Адаптер сверяет `collected` с `goals` уровня. Если игра прислала
`MATCH3_COMPLETE`, но цели по подсчёту не набраны, результат понижается до
`failed` — и сценарий предложит пройти уровень заново. Это защита от
рассинхрона между вашей логикой победы и целями из конфига.

## Стендовый режим

`stand/match3.html` — отдельная точка входа для мероприятий (ТЗ, п. 19). Она
использует ту же страницу игры и тот же контракт сообщений, но не читает и не
пишет прогресс новеллы и сбрасывает сессию после бездействия.

Уровень задаётся параметром: `stand/match3.html?level=stand_cleanup_01`.

# Подключение своих мини-игр

Все мини-игры возвращают один и тот же результат, поэтому движок новеллы не
знает, как они устроены внутри.

```js
class YourAdapter {
  async start ({ container, config, onEvent }) {
    // отрисовать игру в container, дождаться конца
    return {
      status: 'completed',            // completed | failed | aborted
      score: 1200,
      metrics: { foundTargets: 3 },   // любые числа/строки/флаги
      flags: ['goal_reached']
    };
  }

  destroy () {
    // обязательно: снять listeners, timers, canvas, аудио
  }
}

MinigameHost.register('yourType', YourAdapter);
```

Подключите файл в `index.html` рядом с остальными мини-играми, добавьте конфиг
в `data/minigames.json` под ключом `yourType` и вызывайте из сценария:

```js
'minigame yourType your_level_01'
```

# Замена ассетов

## Персонажи

`assets/characters/<роль>/normal.svg` — сейчас там силуэты-болванки.
Роли: `mentor`, `operator`, `analyst`, `coordinator`, `hero`.

Положите свои файлы с теми же именами — сценарий править не нужно. Если формат
другой (`.png`, `.webp`), поправьте `sprites` у персонажа в `js/script.js`:

```js
'm': {
  name: 'Наставник',
  directory: 'mentor',
  sprites: { normal: 'normal.png', happy: 'happy.png', serious: 'serious.png' }
}
```

Появятся новые эмоции — используйте их в сценарии:
`'show character m happy at center with fadeIn'`.

## Фоны

`assets/scenes/*.svg`: `office`, `workstation`, `shore`, `analytics`, `event`.
Рекомендуемое соотношение — 16:9.

## Снимки для мини-игр

`assets/scenes/img_*.svg`. Важно: координаты хотспотов в `data/minigames.json`
заданы **в процентах от размера картинки**, поэтому при замене снимка
проверьте, что отмечаемые объекты остались примерно на тех же местах — или
поправьте `x`, `y`, `r` в конфиге.

## Аудио

- Музыка: `assets/audio/music/` — `menu_loop`, `office_loop`, `field_loop`,
  `tension_loop`.
- Звуки: `assets/audio/sound/` — `click`, `success`, `error`, `notify`, `drone`.

Сейчас это синтезированные WAV-заглушки. Если кладёте `.mp3`/`.ogg`, поменяйте
имена файлов в `monogatari.assets('music', …)` и `monogatari.assets('sounds', …)`
в `js/script.js`.

Вызовы в сценарии уже расставлены:

```js
'play music office loop fade 3'
'stop music with fade 2'
'play sound success'
```

Громкость по умолчанию задана в `js/options.js` (`preferences.Volume`), игрок
может менять её в настройках.

Пересоздать все болванки: `npm run assets`.
